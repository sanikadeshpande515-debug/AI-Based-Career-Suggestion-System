## 1. Abstract
Selecting a well-aligned career path from an ever-expanding array of technical domains is a complex multi-criteria decision problem faced by undergraduate engineering students. This project presents the design and implementation of the **AI-Based Career Suggestion System**, a knowledge-driven artificial intelligence application developed in Python and Streamlit.

The system maintains a domain knowledge base of 20 realistic IT and software professions stored in a CSV repository and evaluates student profiles using six formal **IF–THEN production rules**. Every candidate career is appraised through a weighted scoring engine: technical skills contribute three points (Rule R1), domain interests contribute two points (Rule R2), strong academic subjects contribute two points (Rule R3), eligible degree level contributes two points (Rule R4), preferred work style contributes one point (Rule R5), and experience seniority contributes one point (Rule R6), yielding a maximum possible score of 11 points (100% match).

The scored careers are ranked deterministically and the top five options are presented alongside granular, human-readable explanations detailing exactly why each career was recommended and which rules fired. Because each suggestion is generated by explicit production rules, the system is fully explainable, requires zero training data, and produces deterministic results. Comprehensive functional testing covering valid inputs, empty selections, boundary qualifications, and reproducibility tests demonstrated 100% pass rates.

**Keywords:** Artificial Intelligence, Rule-Based System, Expert System, Career Guidance, Weighted Scoring, Knowledge Base, Explainable AI (XAI), Python, Streamlit.

## 2. Introduction

### 2.1 Background
The rapid diversification of the modern information technology landscape has introduced numerous career specializations—including Cloud Engineering, Data Science, DevOps, UI/UX Design, Cybersecurity, and Blockchain Development. Students frequently experience career ambiguity, unsure of how their academic subject proficiencies, acquired programming languages, and personal workplace traits correlate with industry roles.

Recommender systems broadly adhere to three paradigms:
1. **Collaborative Filtering:** Relies on historical user-item interactions and peer similarity matrices; vulnerable to severe cold-start issues for new students.
2. **Content-Based Machine Learning:** Maps vector embeddings using deep learning; requires substantial training datasets and operates as an unexplainable "black box".
3. **Knowledge-Driven / Rule-Based Systems:** Encodes verified domain expertise into structured **IF–THEN production rules** evaluated by an inference engine.

Knowledge-driven AI is uniquely suited for career counselling because transparency is paramount: students need to understand the logical rationale behind a recommended career.

### 2.2 Problem Statement
To design and implement a knowledge-driven Career Suggestion System that accepts a student's skills, interests, favourite academic subjects, education degree, preferred work style, and experience seniority, validates all inputs, executes a transparent weighted rule engine, and displays the top five career recommendations accompanied by human-readable explanations of all satisfied rules.

### 2.3 Objectives
- To investigate the principles of knowledge-driven artificial intelligence, expert systems, and explainable recommendations.
- To formulate a weighted production rule base comprising skills, interests, subjects, education, work style, and experience criteria.
- To implement a modular three-tier architecture (Presentation, Inference Engine, Data Layer) in pure Python.
- To develop an interactive, professional web application using Streamlit with real-time feedback and profile presets.
- To validate the system against functional black-box and unit test cases.

### 2.4 Scope
The system incorporates 20 curated technical professions stored in `careers.csv`. Recommendations are computed across six attributes: skills, interests, subjects, education, work style, and experience. The application runs locally or on cloud servers without external machine learning libraries (no PyTorch, TensorFlow, or black-box neural networks) and without costly paid external AI APIs.

## 4. System Analysis

### 4.1 Existing Systems
Traditional career websites typically provide static keyword queries or unguided blog posts. Where modern AI tools are introduced, they often deploy generative language models or opaque neural networks that can hallucinate credentials, introduce demographic biases, and fail to provide deterministic, auditable justifications.

### 4.2 Proposed System
The proposed system implements a deterministic, knowledge-driven Expert System. A structured CSV knowledge base defines twenty modern career tracks. At runtime, the user inputs their profile through an intuitive Streamlit interface. The rule engine validates the data, evaluates six production rules against every career record, computes normalized match percentages, applies deterministic multi-key sorting, and displays the top 5 careers with step-by-step reasoning.

## 5. System Design

### 5.1 Workflow Pipeline
1. **Data Ingestion:** Load `careers.csv` into memory via `load_careers()`.
2. **Option Extraction:** Extract unique taxonomy for skills, interests, subjects, and work styles via `get_options()`.
3. **User Profile Acquisition:** Capture student inputs through Streamlit interactive form controls.
4. **Input Validation:** Ensure mandatory selections are provided; reject empty inputs gracefully.
5. **Rule-Based Inference:** Evaluate production rules R1–R6 across all careers.
6. **Deterministic Ranking:** Sort matching careers by match score descending, then matched skills count, then alphabetically.
7. **Explanatory Presentation:** Render top-5 cards with match percentage, progress bars, rule tags, and reasons.

### 5.2 Rule Base Design

$$\text{Score}(c) = 3 \cdot R_1(c) + 2 \cdot R_2(c) + 2 \cdot R_3(c) + 2 \cdot R_4(c) + 1 \cdot R_5(c) + 1 \cdot R_6(c)$$

| Rule ID | Name | Weight | Condition (IF) | Generated Justification |
|:---:|:---|:---:|:---|:---|
| **R1** | Skill Match | **+3** | User skill $\cap$ Career required skills $\neq \emptyset$ | `✓ Skills matched (N): ...` |
| **R2** | Interest Match | **+2** | User interest $\cap$ Career interest domains $\neq \emptyset$ | `✓ Interests matched (N): ...` |
| **R3** | Subject Match | **+2** | User strong subject $\cap$ Career academic subjects $\neq \emptyset$ | `✓ Strong subjects matched (N): ...` |
| **R4** | Education Match | **+2** | User degree level $\in$ Career accepted degrees | `✓ Education requirement satisfied (...)` |
| **R5** | Work Style Match | **+1** | User work style $\cap$ Career work styles $\neq \emptyset$ | `✓ Preferred work style matches (...)` |
| **R6** | Experience Match | **+1** | User seniority $\in$ Career recommended experience | `✓ Experience level matches (...)` |

**Maximum Possible Score:** $3 + 2 + 2 + 2 + 1 + 1 = 11$ Points  
**Match Percentage:** $\min\left(100, \text{round}\left(\frac{\text{Score}}{11} \times 100\right)\right)$

### 5.3 Three-Tier Layered Architecture
- **Presentation Layer (`app.py`):** Interactive Streamlit web interface, form validation alerts, score badges, progress bars, and preset personas.
- **Rule-Based Engine Layer (`career_engine.py`):** Production rules R1–R6, weighted scoring arithmetic, deterministic ranking module, and explanation string generator.
- **Data Layer (`careers.csv`):** Knowledge base containing twenty career profiles with semicolon-delimited multi-value attributes.

## 6. Algorithms Used

### Algorithm 1: Rule-Based Weighted Scoring and Explanation Generation
```
Require: Career Knowledge Base C = {c1, c2, ..., cN}, User Profile U
Ensure: Ranked Top-5 Career Recommendations with Explanations R

1:  candidates ← []
2:  for each career c in C do
3:      score ← 0
4:      rules_fired ← []
5:      reasons ← []
6:      
7:      // Rule 1: Technical Skill Match
8:      matched_skills ← user_skills ∩ career_skills(c)
9:      if matched_skills ≠ ∅ then
10:         score ← score + 3
11:         append "R1: Skill Match (+3)" to rules_fired
12:         append ("✓ Skills matched: " + matched_skills) to reasons
13:     end if
14:     
15:     // Rule 2: Domain Interest Match
16:     matched_interests ← user_interests ∩ career_interests(c)
17:     if matched_interests ≠ ∅ then
18:         score ← score + 2
19:         append "R2: Interest Match (+2)" to rules_fired
20:         append ("✓ Interests matched: " + matched_interests) to reasons
21:     end if
22:     
23:     // Rule 3: Academic Subject Match
24:     matched_subjects ← user_subjects ∩ career_subjects(c)
25:     if matched_subjects ≠ ∅ then
26:         score ← score + 2
27:         append "R3: Subject Match (+2)" to rules_fired
28:         append ("✓ Strong subjects matched: " + matched_subjects) to reasons
29:     end if
30:     
31:     // Rule 4: Education Qualification Match
32:     if user_education ∈ career_education(c) then
33:         score ← score + 2
34:         append "R4: Education Match (+2)" to rules_fired
35:         append ("✓ Education requirement satisfied") to reasons
36:     end if
37:     
38:     // Rule 5: Work Style Match
39:     matched_styles ← user_work_styles ∩ career_work_styles(c)
40:     if matched_styles ≠ ∅ then
41:         score ← score + 1
42:         append "R5: Work Style Match (+1)" to rules_fired
43:         append ("✓ Preferred work style matches: " + matched_styles) to reasons
44:     end if
45:     
46:     // Rule 6: Experience Level Match
47:     if user_experience ∈ career_experience(c) then
48:         score ← score + 1
49:         append "R6: Experience Match (+1)" to rules_fired
50:         append ("✓ Experience level matches") to reasons
51:     end if
52:     
53:     if score > 0 then
54:         pct ← round((score / 11) * 100)
55:         append (c, score, pct, rules_fired, reasons, |matched_skills|) to candidates
56:     end if
57: end for
58: 
59: sort candidates by:
        (-score, -|matched_skills|, -|matched_interests|, career_name)
60: return first 5 elements of candidates
```

**Complexity Analysis:**
- Rule Evaluation: $O(N \cdot K)$, where $N = 20$ careers and $K = 6$ rules ($O(1)$ operations per career).
- Sorting: $O(N \log N)$ using Python's stable Timsort.
- Total Runtime: $< 5$ milliseconds on commodity hardware.

## 10. Advantages and Limitations

### Advantages
- **100% Explainable & Auditable:** Eliminates the opaque decision-making of neural networks.
- **No Cold Start or Training Overhead:** Operates immediately without historical data.
- **Deterministic:** The exact same inputs always yield identical suggestions.
- **Easy Domain Maintenance:** New career options or rules can be added directly via CSV.

### Limitations
- **Static Knowledge Scope:** Requires manual updates to incorporate newly emergent job titles.
- **Discrete Exact-Match Evaluation:** Does not infer semantic synonyms (e.g., "coding" vs "programming") without explicit ontology mappings.
